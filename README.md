# arr_dour

[![Build](https://github.com/ultrasardine/arr_dour/actions/workflows/build.yml/badge.svg)](https://github.com/ultrasardine/arr_dour/actions/workflows/build.yml)

`arr_dour` is a fork of [Ardour](https://ardour.org), the open-source digital
audio workstation. Its goal is to make building and running Ardour from source
straightforward on **Debian**, **macOS**, and **native Windows**, using one
short command per task and without a separate build-tools repository.

The audio engine and user interface are upstream Ardour. This fork adds:

- A root `Makefile` for Debian and macOS (`make build`, `make run`, …) with
  grouped `make help` output and setup guidance when configuration fails.
- A repository-owned macOS Homebrew dependency manifest
  (`tools/macos/Brewfile`) and an environment wrapper
  (`tools/macos/build-env.sh`), so no hand-built dependency stack is needed.
- PowerShell scripts for native Windows MSVC builds (`tools/windows/`).
- Small build-system portability fixes (see
  [Changes from upstream](#changes-from-upstream)).
- CI that builds Debian and macOS on every push and pull request.

The commands wrap Ardour's existing Waf build. They produce a development build
that runs from the source tree; they do not build installers, `.app` bundles,
or install Ardour system-wide.

## Quick start

| Platform | One-time setup | Build | Run |
| --- | --- | --- | --- |
| Debian 12/13 | `sudo apt install …` ([list](#debian)) | `make build-debian` | `make run-debian` |
| macOS (Apple Silicon/Intel) | `xcode-select --install`, [Homebrew](https://brew.sh), `make deps-osx` | `make build-osx` | `make run-osx` |
| Windows 10/11 x64 | Visual Studio Build Tools + MSVC dependency stack ([details](#native-windows-powershell)) | `.\tools\windows\build.ps1 -DependencyRoot C:\ardour-stack` | `.\tools\windows\run.ps1 -DependencyRoot C:\ardour-stack` |

All platforms first need a full clone with Ardour release tags; see
[Source checkout](#source-checkout). Run `make help` for every task.

## Source checkout

Use a full Git clone, not GitHub's autogenerated source archive:

```sh
git clone https://github.com/ultrasardine/arr_dour.git
cd arr_dour
git describe HEAD
```

Ardour derives its version from release tags. `git describe HEAD` must succeed
before configuring. If your clone is shallow, unshallow it; fetch tags with
`git fetch --tags origin`. If the fork has not published Ardour's release tags,
fetch them from the upstream repository:

```sh
git fetch https://github.com/Ardour/ardour.git --tags
git describe HEAD
```

The upstream tag must be reachable from this fork's history; do not invent a
version tag to bypass this requirement. See `README-GITHUB.txt`.
Use checkout and dependency-stack paths without spaces: several upstream build
rules and development launchers use unquoted paths.

## Debian

Install build dependencies (Debian 12/13):

```sh
sudo apt update
sudo apt install build-essential git python3 pkg-config gettext \
  libboost-dev libglib2.0-dev libglibmm-2.4-dev libsigc++-2.0-dev \
  libcairomm-1.0-dev libpangomm-1.4-dev libpango1.0-dev \
  libpng-dev libjpeg-dev libxml2-dev libsndfile1-dev \
  libcurl4-openssl-dev libarchive-dev liblo-dev libtag1-dev \
  vamp-plugin-sdk librubberband-dev libsamplerate0-dev libfftw3-dev \
  libflac-dev libogg-dev libaubio-dev liblrdf0-dev \
  lv2-dev libserd-dev libsord-dev libsratom-dev liblilv-dev \
  libasound2-dev libx11-dev libxext-dev libusb-1.0-0-dev
```

Then build and launch from the checkout:

```sh
make build-debian
make run-debian
```

The default audio backend is ALSA (the dummy backend is also built).
For JACK support, install `libjack-jackd2-dev` and use
`make run-debian BACKENDS=alsa,jack`. A graphical desktop and an accessible
audio device are needed to run the GUI.

## macOS

Install Xcode Command Line Tools and [Homebrew](https://brew.sh). This fork
declares the dependencies in `tools/macos/Brewfile`; no separate Ardour
build-tools checkout or hand-built dependency stack is required by these tasks.

```sh
xcode-select --install
make deps-osx
make configure-osx
make build-osx
make run-osx
```

`make deps-osx` installs the declared Homebrew packages, including legacy C++
bindings compatible with the APIs used here. `tools/macos/build-env.sh` sets
the package search paths and Boost, gettext, and JPEG include/library paths
for configure, build, and run. There are no exports to copy into your shell.
Unlike configure/build/run, the dependency task intentionally installs packages.
The Homebrew route has completed a full native build on Apple Silicon, and the
development launcher successfully runs `--help`. Interactive GUI, audio-device
operation, and Intel builds still need verification.
The bundled YDK/YTK libraries disable ELF symbol aliases on macOS, where the
Mach-O object format does not support them.
Public library headers export their libarchive, FFTW, and sndfile include paths
through Waf so consumers can use Homebrew's isolated installation prefixes.

CoreAudio is the default backend. Builds use the host architecture, including
Apple Silicon; all dependencies must match it. `make run-osx` launches directly
from the build tree, not from a packaged `.app` or `.dmg`.

## Make commands and options

Run these commands from the repository root. `make build` and `make run`
auto-select ALSA on Linux or CoreAudio on macOS. The platform-specific aliases
reject the wrong host.

| Command | Action |
| --- | --- |
| `make help` | Show available targets and overrides |
| `make prerequisites` | Print tool/library installation and environment setup instructions |
| `make prerequisites-debian` / `make prerequisites-osx` | Print platform-specific setup instructions without installing anything |
| `make configure` | Configure Waf without building |
| `make build` | Configure, then incrementally build |
| `make run` | Configure/build, then launch via `gtk2_ardour/ardev` |

Defaults are four build jobs and an optimized, English-only build.
Dependencies are installed only by `make deps-osx`, not by build/run. On a configure failure, Make prints
platform-specific installation commands, dependency-stack environment settings,
and version-tag troubleshooting. Additional error details are in `build/config.log`.

```sh
make build JOBS=8
make build CONFIGURE_FLAGS="--test --single-tests --no-nls"
make run ARGS='--help'
make run ARGS='"/absolute/path/to/My Session"'
```

`CONFIGURE_FLAGS` replaces the default `--optimize --no-nls` flags, so omitting
`--optimize` selects Waf's default debug build. `BACKENDS`, `PYTHON`, and
`BUILD_FLAGS` are also configurable. Each build reconfigures so changes to
these options take effect. Native compiled artifacts remain in `build/`.

## Native Windows (PowerShell)

The scripts use Waf's existing **x64 MSVC** target; they do not use WSL or the
Linux/MinGW cross-compilation scripts.

Prerequisites:

- Visual Studio Build Tools with Desktop development with C++ and a Windows
  SDK. Run the scripts in an **x64 Developer PowerShell** so `cl`, `link`,
  `rc`, and `ml64` are available.
- Native Windows Python 3, Git, `pkg-config`, and LLVM's `llvm-nm` on `PATH`.
- A prebuilt **MSVC-compatible x64 Ardour dependency stack** with `bin`,
  `include`, `lib`, and `lib/pkgconfig` directories. MinGW/MSYS2 C++ binaries
  are not ABI-compatible with this MSVC workflow.

The stack must provide the libraries checked by the root and component
`wscript` files, including Boost, GLib/glibmm/giomm, sigc++, Cairo/cairomm,
Pango/pangomm, Fontconfig, PNG/JPEG, XML, sndfile, curl, archive, liblo,
TagLib, Vamp, Rubber Band, samplerate, FFTW, FLAC/Ogg, the LV2/Lilv stack,
and PortAudio. It must also provide pthreads libraries named `pthreadVC3`
(optimized) or `pthreadVC3d` (debug), as expected by Waf. Dependency DLLs
belong in the stack's `bin`; `.pc` files must reference that stack.
These scripts do not download or build the dependency stack.

From the checkout, substituting your actual stack path:

```powershell
.\tools\windows\build.ps1 -DependencyRoot C:\ardour-stack
.\tools\windows\run.ps1 -DependencyRoot C:\ardour-stack
```

`run.ps1` builds first, configures DLL/resource search paths for the development
tree, then waits for Ardour to exit. Both scripts restore the caller's working
directory and modified environment variables, and report nonzero exit codes.

```powershell
.\tools\windows\build.ps1 -DependencyRoot C:\ardour-stack -Jobs 8
.\tools\windows\build.ps1 -DependencyRoot C:\ardour-stack -ConfigureArgs @('--no-nls')
.\tools\windows\run.ps1 -DependencyRoot C:\ardour-stack -SkipBuild
.\tools\windows\run.ps1 -DependencyRoot C:\ardour-stack -AppArgs @('C:\Sessions\My Session')
```

Use `-Python` to choose a Python executable, `-ConfigureArgs` to replace the
default `--optimize --no-nls`, and `-BuildArgs` to add Waf build options.
For a debug build, provide the matching debug dependency libraries.
If local execution policy blocks scripts, follow your organization's policy
for allowing reviewed local scripts.

## Tests

The wrapper regression tests require only Python 3 and Make:

```sh
python3 -m unittest discover -s tools/tests -p 'test_dev_commands.py'
```

When `pwsh` is on `PATH`, this also parses and exercises the PowerShell scripts
with simulated compiler/application commands. Actual native compilation and
GUI startup still require each platform and its dependency stack.

For engine tests, configure with `--test` and use the library runners described
in `doc/unit_tests.txt` and `.github/copilot-instructions.md`.

## Packaging and `.app` bundles

`make build-osx` produces a development build in `build/`, launched by
`gtk2_ardour/ardev` (via `make run-osx`). It is not an `Ardour.app`: a
distributable macOS bundle must copy every Homebrew dylib into the bundle,
rewrite their install names, and sign and notarize the result. Upstream's
packaging scripts (`tools/osx_packaging/`) expect Ardour's own dependency stack
rather than Homebrew, so they are not wired into this fork's Make tasks yet.
The same applies to Windows installers and Debian packages.

## Troubleshooting

| Symptom | Fix |
| --- | --- |
| `make: *** No rule to make target 'help'` | Run Make from the repository root of a checkout that contains this fork's `Makefile`. |
| `Cannot determine Ardour's version from Git tags` | Fetch upstream tags: `git fetch https://github.com/Ardour/ardour.git --tags`, then check `git describe HEAD`. |
| `Checking for boost library >= 1.68 : no` (or another `Checking for …: no`) | macOS: run `make deps-osx`. Debian: install the `apt` packages above. Details are in `build/config.log`. |
| `Missing Homebrew dependency: <name>` | Run `make deps-osx`; the Brewfile was updated or a package was removed. |
| A header such as `archive.h` is not found while compiling | Make sure the matching dependency is installed, then rerun the build. If it persists on macOS, report it: a Waf target probably needs to export that include path. |
| Configure options seem ignored | Each `make build` reconfigures. Pass options through `CONFIGURE_FLAGS`, which replaces the defaults. |
| Builds from a path with spaces fail | Move the checkout or dependency stack to a path without spaces. |

Use `make prerequisites` to print the setup instructions for your platform.

## Continuous integration

`.github/workflows/build.yml` runs on pushes to `master`, pull requests, and
manual dispatch:

- **Wrapper tests** on Ubuntu, macOS, and Windows (Windows runs the PowerShell
  tests only).
- **Debian 12**: installs the documented `apt` packages, runs
  `make build-debian`, then `ardev --version`.
- **macOS (Apple Silicon)**: runs `make deps-osx`, `make build-osx`, then
  `ardev --version`.

The fork does not publish Ardour's release tags, so CI fetches them from the
upstream repository before configuring.

## Changes from upstream

Build portability fixes made so the Homebrew and Git-worktree workflows build
cleanly. These are small and isolated so upstream merges stay easy:

| Area | Change |
| --- | --- |
| `wscript` | Detect Git worktrees (where `.git` is a file) and print an actionable error when `git describe` fails. |
| `libs/tk/ydk/wscript`, `libs/tk/ytk/wscript` | Define `DISABLE_VISIBILITY` on macOS; Mach-O does not support the ELF symbol aliases used by the bundled GTK. |
| `libs/pbd/wscript`, `libs/ardour/wscript`, `libs/audiographer/wscript` | Export libarchive, FFTW, and sndfile include paths to dependent targets. |
| `gtk2_ardour/wscript` | Add `SNDFILE` to the GUI executable's dependencies. |
| LV2 plugins and three GUI sources | Include `<cairo.h>` instead of `<cairo/cairo.h>`. |
| `libs/surfaces/console1` | Include `<glibmm/…>` instead of `<glibmm-2.4/glibmm/…>`. |
| `.gitignore` | Track the root `Makefile`. |

## Syncing with upstream

```sh
git remote add upstream https://github.com/Ardour/ardour.git
git fetch upstream --tags
git merge upstream/master
make build
```

After merging, rerun the wrapper tests and a full build. New upstream
dependencies may need to be added to `tools/macos/Brewfile`, the Debian package
list (in this README, `tools/build-prerequisites.sh`, and CI), and the Windows
dependency stack notes.
